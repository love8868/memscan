# memscan —— CE 替代版（自动化优先）

Cheat Engine "搜数值→过滤→修改"流程的自动化 Python 实现。
**设计目标不是抄 CE，而是把 CE 里手动来回点的环节全部自动化掉。**

## 文件

| 文件 | 说明 |
|---|---|
| `memscan.py` | 核心：双后端（Linux/Windows）+ Scanner（精确/模糊/多类型扫描） |
| `unknown_scan.py` | 未知初始值搜索（血条看不到数字时用） |
| `locker.py` | 地址锁定（后台线程定时重写，CE 的 freeze） |
| `cheattable.py` | CT 表存取（JSON，下次直接加载） |
| `cli.py` | **交互式命令行**，向导式操作入口 |
| `fakegame.py` | 假游戏进程（测试用） |
| `test_scan.py` / `test_v2.py` | 自动化测试 |
| `README.md` | 本文件 |

## 和 CE 的对比：自动化高在哪

| 场景 | CE（手动） | memscan（自动） |
|---|---|---|
| 不知道数值类型 | 手动选 i32/f32…逐个试 | `find` 向导并行扫 4 种类型，自动推荐收敛最好的 |
| 血条看不到数字 | 手动选 "Unknown initial value"，手动点 changed/unchanged | `ufind` 向导一步步带，自动多轮过滤 |
| 改完被游戏改回去 | 手动勾选 freeze | `lock` 一键锁定，后台 0.1s 重写 |
| 下次还要用 | 手动另存 .CT | `save`/`load`，锁定项自动恢复 |

## 快速上手（Windows）

```powershell
pip install pymem
# 管理员身份运行 PowerShell（部分游戏需要）
python cli.py
```

```
memscan> attach game.exe
已附加到进程 game.exe
memscan> find
现在的数值是多少？ 100
正在并行扫描 i32/u32/f32/i64 ...
  i32: 3182 个候选
  f32: 5 个候选
去游戏里改变数值，输入新数值后回车（q 退出）：125
  i32: 1 个候选
✅ 锁定类型 i32，剩 1 个候选：
  [0] 0x7e50e7e881a0 (i32) 当前值=125
用 write <序号> <值> 修改，或 lock <序号> <值> 锁定
memscan> lock 0 9999
✅ 已锁定 0x7e50e7e881a0 = 9999（每 0.1s 重写）
memscan> save 今天的表.json

```

下次：
```
memscan> attach game.exe
memscan> load 今天的表.json
✅ 加载 1 项，其中 1 个恢复锁定
```

## 找得准：两个实战杀招

**1. 混淆值搜索（findx）**——很多游戏不存原值，存 `原值*8` 这种。
你搜 100，内存里是 800，普通搜索永远搜不到：
```
memscan> findx 100 *8
正在搜索 显示值=100 变换=*8 ...
首搜 12 个候选。去游戏里改变显示值，
输入显示值变化量（如花了50金币就输 -50，q 退出）：-5
差值过滤后剩 1 个候选
  [0] 0x74c42519e6f4 (i32) 显示值=95 (内存值=760)
memscan> writex 0 200     # 按显示值写，自动换算成 1600
```
变换支持 `*8`、`/2`、`+100`、`-5`，可组合如 `*8+10`。

**2. 差值过滤（by）**——"花了 50 金币"比"金币变小了"精确得多：
```
memscan> by -50
差值过滤后剩 1 个候选
```
实测一轮收敛。配合 findx 会自动换算显示差值→内存差值。

## 练手：假游戏里的科技系统

`fakegame.py` 现在带一套完整科技系统，开两个终端练全流程：

终端1：`python3 fakegame.py`（看它每 2 秒打印的状态）
终端2：`python3 cli.py`

**路线 1：科研点数（精确搜索）**
```
memscan> attach <PID>     # PID 看终端1第一行
memscan> find
现在的数值是多少？ 500
  i32: 9 个候选 ...
去游戏里改变数值（等几秒，点数会被消耗成 490），输入新数值：490
✅ 锁定类型 i32，剩 1 个候选
memscan> lock 0 9999      # 点数锁死，随便点科技
```

**路线 2：研究计时器（未知搜索，decreased）**
```
memscan> ufind
正在拍内存快照 ... 好了回车 ...
数值怎么变的？ decreased
类型？i32
剩 N 个候选 → 再等几秒 → decreased → 收敛到计时器地址
memscan> write 0 1        # 改成 1 秒，研究秒完成
```

**路线 3：科技数组（相邻地址规律）**
```
# 先用 find 找到某个科技等级（比如 3）
# 它的相邻地址 +4、+8、+12 就是其他科技
# 实测：[3, 2, 5, 1] 连续存放，一次改一排
```

## 完整命令

```
attach <pid|进程名>   附加（Linux 用 pid，Windows 用进程名）
find                 向导：精确数值查找（自动试全部类型）
ufind                向导：未知数值查找（血条时用）
list                 显示当前候选
write <序号> <值>     修改
lock <序号> <值>      锁定 / unlock <序号> 解除 / locks 查看
save <文件>          存 CT 表
load <文件>          读 CT 表（锁定项自动恢复）
pointers <序号>      找指向该地址的指针
type <类型>          默认类型 i32/u32/f32/i64
quit                 退出
```

## 边界

- ✅ 单机游戏分析研究
- ❌ 网游（服务器会纠正 + 封号）
- ❌ 不做自动代打/外挂（既定规矩）

## 刻意不做的（CE 的硬骨头）

调试器、代码注入、变速 hack、多级指针链全自动搜索——复杂 10 倍，收益不成正比，留给 CE。
